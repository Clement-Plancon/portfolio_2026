W—03 · Case study

SafePing

Application mobile de sécurité personnelle, pensée pour les situations où un téléphone ne doit pas trahir celui qui le porte. Mode façade, contacts de confiance, GPS optionnel, zéro compte.

Rôle
Design · Architecture · Dev
Contexte
Projet d'auteur · privacy-first
Période
2025 — en développement
Stack
Flutter · Dart · Local-first
01
Overview

SafePing est une application mobile pensée pour une catégorie précise d'usagers : des personnes exposées, parfois accompagnées, qui ont besoin de pouvoir déclencher une alerte sans que le téléphone n'ait l'air d'une app d'alerte.

L'app se présente comme une appli de notes anodine. Un geste connu de l'utilisateur bascule en mode SOS, envoie un message à des contacts prédéfinis, et peut partager une position si l'utilisateur l'a autorisée en amont. Aucune donnée ne quitte l'appareil tant qu'il n'y a pas d'alerte active.

02
Le problème

Les apps de sécurité existantes partent du principe que le téléphone est une alliée visible. Dans les situations où le téléphone peut être inspecté — violences conjugales, situations à risque — cette hypothèse ne tient pas.

L'app devait disparaître dans le paysage de l'appareil, être simple à expliquer en deux minutes, et ne pas demander de compte ni de configuration cloud.

03
Approche
  • Mode façade — Interface de notes convaincante : on peut y écrire, les notes sont persistées, elles ont l'air réelles.
  • Déclencheur caché — Un geste précis, choisi par l'utilisateur, active le mode SOS. Pas de bouton visible.
  • Local-first — Tout vit dans l'appareil. Les contacts de confiance sont enregistrés localement, le canal d'envoi est SMS natif en premier recours.
  • Zéro compte — Pas d'inscription, pas de serveur, pas de connexion internet obligatoire pour le fonctionnement courant.
04
Décisions & compromis

Flutter plutôt que natif

Projet d'auteur, une seule base de code pour iOS et Android. Les sensibilités tactiles exigeaient quelques patchs natifs, mais Flutter couvre 90% du besoin sans compromis sur la réactivité.

Pas de cloud par défaut, point.

La tentation existait de proposer "une synchronisation sécurisée". Elle a été écartée. Un backend crée une surface qu'on ne peut pas garantir à cent pour cent. Le choix a été de rester local, et d'assumer qu'un changement de téléphone demande une reconfiguration — c'est le prix de la discrétion.

Pas de notifications

L'app ne pousse rien. Elle n'apparaît pas dans la barre d'état. Elle ne demande que les permissions nécessaires au moment où elles le sont, pas en bloc à l'installation.

05
Statut & suite

En développement. Les parcours principaux fonctionnent, le mode façade est stable, le déclencheur est en calibration. L'étape suivante est un cycle de tests dans un cadre associatif, avec des usagers réels, pour vérifier que la gestuelle reste discrète en situation.

Je ne communique volontairement pas de date de sortie. Un outil de ce type ne sort pas tant qu'il n'est pas prêt.
